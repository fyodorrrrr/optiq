## Findings

### P1 — Map group headings fail text contrast

- Location: `frontend/src/App.css:612–623`.
- Category: Accessibility / Theming.
- Evidence: `#8a847b` at opacity .50 over white produces approximately **1.78:1** contrast. Browser computed styles confirm the color and opacity at all four widths. These are real h3 headings with accessible labels, not purely decorative marks.
- Impact: Foundations, Features & recognition, and Detection & segmentation are difficult to read, particularly for low-vision users.
- Standard: WCAG 1.4.3 (AA). This is below both 4.5:1 for normal text and 3:1 for large text.
- Recommendation: Preserve the handwritten treatment, use an opaque semantic text token and verify at least 4.5:1 at its smallest size.
- Suggested command: `$impeccable colorize`.

### P2 — Sighted users cannot distinguish concept illustrations from computed output

- Location: `frontend/src/components/LabPreview.tsx:25–26,41–47`.
- Category: Implementation Integrity.
- Evidence: Labs 5 and 6 retain explicit illustrative disclaimers in alt text, but removing figcaptions removed the visible qualification. Other lab previews are actual algorithm outputs. The Lab 6 artwork depicts a “glass” detection, which could be read as a prediction.
- Impact: Users can mistake teaching artwork for an executed experiment.
- Standard: Product requirement to distinguish illustrative examples and real computation; not asserted as a WCAG failure.
- Recommendation: Keep the approved caption-free appearance; incorporate a short clarification into the existing description for these two previews, rather than restoring the removed captions.
- Suggested command: `$impeccable clarify`.

### P2 — Comparison descriptions describe obsolete layouts

- Location: `frontend/src/components/LabPreview.tsx:21–27`; `frontend/src/components/PreviewComparison.tsx:2`.
- Category: Accessibility / Implementation Integrity.
- Evidence: Shared descriptions say “beside” despite the fixed split. Lab 3 additionally promises measured histograms in the thumbnail, but its rendered comparison uses before/after images rather than the combined histogram thumbnail.
- Impact: Screen-reader users receive a description containing content absent from the presented image.
- Standard: WCAG 1.1.1 relevance of text alternatives.
- Recommendation: Describe the actual split image and remove the histogram claim from the description used by the fixed comparison.
- Suggested command: `$impeccable clarify`.

### P2 — Mobile image sizing depends on preview implementation

- Location: `frontend/src/components/LabPreview.tsx:42–45`; `frontend/src/App.css:745,890–892`.
- Category: Responsive Design.
- Evidence: On mobile, Labs 1–3/7 now use the 4:3 comparison stage while Labs 4–6 use a thumbnail capped at 180px height. Comparison stages do not receive this cap. Desktop illustrated stages and mobile thumbnails also use different surface wrappers.
- Impact: The selected image changes footprint by lab, weakening the intended stable, compact preview presentation. This is a consistency issue, not observed horizontal overflow.
- Recommendation: Apply one responsive frame and image-containment policy across computed comparisons, matching output and illustrations, preserving their aspect ratios.
- Suggested command: `$impeccable adapt`.

### P3 — Design documentation contradicts the current homepage

- Location: `docs/DESIGN_FOUNDATION.md:75–78,128–139`.
- Category: Implementation Integrity.
- Evidence: Documentation describes availability labels and pending custom training, group text at 85% opacity, Lab 6's slider and the previous image-card treatment. Current source uses numbered labels, .50 heading opacity, a static Lab 6 illustration and fixed comparisons.
- Impact: Future changes based on this document can reintroduce obsolete behavior or inconsistent styling.
- Recommendation: Update only these factual implementation descriptions, retaining approved visual decisions. This audit does not repair documentation as a side effect.
- Suggested command: `$impeccable document`.

### P3 — Removed preview UI leaves unused data and image references

- Location: `frontend/src/components/LabPreview.tsx:12–27`.
- Category: Performance / Implementation Integrity.
- Evidence: Every `caption` field remains although none is rendered. Combined thumbnails for Labs 1–3/7 remain referenced in the preview record even though comparisons now render at both viewport modes. The fixed comparison map means those image branches are not selected for these labs.
- Impact: Extra maintenance and production assets without current UI use. This audit does not claim those images are all downloaded or that removing them measurably improves load time.
- Recommendation: Remove unused caption data/imports from this component; retain exported assets if their provenance/documentation purpose remains useful.
- Suggested command: `$impeccable optimize`.

## Patterns and positives

The main pattern is drift after a presentation change: accessible descriptions, unused data, responsive branches and documentation still describe earlier preview behavior. Update these together when the preview contract changes.

Maintain the shared palette, explicit focus styles, real buttons/links, skip link, logical main/section headings, aria-pressed selection and explanatory image alternatives. All seven lab selectors worked through keyboard activation at every checked width. Center-point hit tests found no intercepted lab buttons. No missing img alt attributes, horizontal overflow or runtime page errors were observed. Emerald buttons with white text measure approximately 5.08:1; supporting gray text on paper measures 5.43:1. Lab routes are lazy-loaded; illustrations use compact WebP assets. Reduced motion disables Lenis and preserves static map selection feedback.

## Verification and limitations

Inspected homepage source, local running page and full-page screenshots at 1440×900, 768×900, 390×900 and 320×900. Browser evidence is in `/private/tmp/optiq-home-audit/` (temporary, not committed). Detector targets included App, LabMap, LabPreview, PreviewComparison, LearningCards and shared homepage styles; zero findings.

No production Lighthouse/Core Web Vitals, screen-reader session, complete WCAG audit or device hardware testing was performed. Changing root font size caused no overflow but many font sizes are in pixels, so this does not establish 200% text-resize compliance. Small-target scan flagged the 42px-tall brand link and hidden skip link; these are not reported as AA target-size failures because the 44px recommendation is not the WCAG 2.2 AA minimum and the skip link was measured unfocused. No app code changed.
